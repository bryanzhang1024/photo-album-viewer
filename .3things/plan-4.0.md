# 4.0 界面重做 · 实施计划

状态：计划阶段产物（2026-10-25），待用户批准。批准前不动产品代码。

对照基准：`design-book.html`（38 屏实时设计稿）、`shell-spec-final.md`（19 条 + 修订）、`ui-coverage-4.0.md`（界面 × 功能清单）、当前 3.13.1 代码。

## 一、结论：功能和 UI 各自是什么情况

**这是一次界面层重写，不是后端重写。** 目录扫描、缩略图管线、HEIC/AVIF 解码、Cos 索引、收藏存储、废纸篓、多窗口、随机浏览、双页查看全部复用；主进程只加两个很小的接口。

按 38 屏设计稿拆开看：

| 类型 | 数量 | 说明 |
|---|---|---|
| 纯界面重写（行为不变） | 26 屏 | 颜色、字号、间距、结构全部照搬样张，数据和交互沿用 |
| 渲染层行为调整 | 8 处 | 打开方式、收藏列表、每文件夹记忆、完整显示、快捷键、设置四标签、头部两版、标签栏交互 |
| 主进程新增小能力 | 2 个 | 列非图片文件、用系统播放器打开文件 |
| 明确不做 | 9 项 | 见设计稿第十五节，界面不出现入口 |

所以回答你的问题：**不需要开发大功能；需要新增的只有两个小接口和八处交互调整**，其余是把界面按设计稿重写一遍，并保证现有能力一项不少。

## 三、需要新开发的功能

1. **非图片文件列表（主进程）**
   现状：扫描时已经遍历到视频 / 压缩包，但只统计数量，不返回名字和大小。
   要做：新增 `list-directory-files-v1`，只读、只当前目录、不递归，返回 `{name, ext, size, mtimeMs, kind}`，`kind` 映射为 视频 / 压缩包 / 文稿 / 其他。
   为什么单开通道：v1 目录契约带严格校验、被现有页面消费，不改它，避免牵动旧逻辑。
2. **用系统播放器打开文件（主进程）**
   新增 `open-path-external`：只允许已注册根内的文件，`shell.openPath`，失败给可读提示。
   为什么：视频、压缩包在列表里有了入口，就需要一个打开的出口；现有只有「在 Finder 中显示」。
3. **收藏页列表视图（渲染层）**：复用通用列表，列：名称 / 类型 / 张数 / 收藏时间。
4. **每个文件夹分别记住视图与排序（渲染层）**：按 根 + 路径 存；默认网格、名称升序；设置里可关。
5. **完整显示开关（渲染层）**：默认裁切，按文件夹记住。
6. **打开方式（渲染层）**：网格单击打开（心形、角标拦截）；列表单击选中、双击或回车打开；撤销 3.11 的统一双击。
7. **快捷键（渲染层）**：⌘, 打开设置窗口（已有 IPC）、⌘W 关闭当前标签（已有 closeTab）。
8. **设置四标签（渲染层）**：通用 / 浏览 / 缓存 / 图库；现有设置项归位，图库标签只读状态 + 刷新索引。
9. **头部两版（渲染层）**：网格方案一、列表与窄窗方案二，按视图和宽度切换。

## 四、技术方案

- **新界面**：`src/ui/`，design（从样张 CSS 提 token）、shell、features、data、hooks。不 import `src/renderer` 任何东西；只复用 `src/common`、主进程服务和 `public/index.html` 模板。
- **入口并存**：webpack 增一个 `ui` 入口，用环境变量切换；开发期两套界面都能跑，默认仍是旧界面，S7 才切换。
- **数据层**：`src/ui/data/*` 封装现有 IPC，组件不直接 invoke；缩略图 URL 预算逻辑在新界面里复制一份。
- **状态**：每个标签一份 reducer（位置、历史、视图、排序），context + reducer，不引 Redux。
- **迁移**：收藏走 `favorites.json`，不变；标签会话、视图、排序在 localStorage，新界面首启用旧 key 初始化一次，之后用自己的 key（若切回旧界面，这几项偏好会重置，记入风险）。
- **设计基准**：每片用同一窗口尺寸截图，与 `design-book.html` 对应屏并排比对；写一个截图脚本固定跑。

## 五、分步计划

每片都满足：能在分支上跑、用户能看到明确变化、旧界面不受影响。合并目标是长期分支 `codex/ui-rewrite-v4`；`main` 保持 3.13.1，4.0.0 一次性合入。

### S0 地基（小）

- 做什么：新入口与空壳；从样张提取颜色 / 字号 / 间距 token；封装数据层；截图比对脚本；首启偏好迁移。
- 你会看到：新界面能启动，有侧栏、工具栏、空白内容区，观感与样张一致。
- 验收：与 2.x 的外壳结构一致（静态）；旧界面启动不受影响。
- 风险：入口并存配置出错会同时影响两套界面 → 用独立入口和环境变量，构建后先跑旧界面 smoke。

## 六、验收与测试策略

- 每片跑：保留的主进程测试 + 新界面的行为单测（打开方式、每文件夹记忆、完整显示、文件列表合并）+ `npm run build`。
- 每片截图：同窗口尺寸与新界面并排，脚本固定输出到 `.3things/design/verify/`。
- 安装检查点：S1、S2、S4、S7。默认沿用以前的做法：先备份，再临时替换 `/Applications`；你要求独立预览版就改。
- 最终走查清单：38 屏逐屏 + 真实操作（浏览、排序、搜索、收藏、删除、双页、视频、离线）。

## 七、风险与回滚

- **最脆弱的假设**：样张是手写 CSS，1:1 移植到 React 后，3,055 张平铺和 9,591 套 Cos 的滚动性能仍达标。若不成立，先改渲染策略（分页 / 窗口化），不改设计；这条在 S1 与 S4 各验一次。
- **回滚**：`main` 全程不换，标签 `backup/pre-ui-rewrite-3.13.1`；4.0 前后都能一键回旧界面。
- **行为改动风险**：打开方式、每文件夹记忆会改变手感，S1 装预览版时请你重点验。
- **测试空窗**：旧界面测试退役后，S7 前靠新测试加真机；每片验收不通过不进下一片。

## 八、工作量与节奏

- 8 个切片，约 10–14 个可验收轮次；S1、S4 最大，S0、S6 最小。
- 每个切片结束都有一个能跑的新版本，旧界面始终可用；实际日历时间取决于你验收的间隔。

## 九、批准后先做什么

从 S0 开始，做完给你看空壳和截图；S1 结束装预览版。若你希望先做别的切片（例如先做 Cos），现在说，顺序可以换，切片本身不变。
