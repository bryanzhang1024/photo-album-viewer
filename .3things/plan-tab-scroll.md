## 实现与验证步骤

1. App 按标签和页面持有内存中的滚动锚点、偏移与加载范围；激活页面重新挂载，防止同目录标签共用实例。搜索词按页面保留，使恢复所对应的结果集一致；关闭标签释放记忆。
2. VirtualGrid 与 FolderList 共用恢复 hook，在数据和尺寸就绪后恢复 DOM 位置并同步虚拟可视行。COS 两条分页链路先读取旧范围；照片 IPC 每次最多 1000 张，超出时继续补页再定位，避免被首批高度截断。
3. 先运行会失败的回归测试，再修复并通过；全量测试使用项目现有 Node 22。执行 check:unwired、diff --check、npm run build。真实 Electron 隔离 profile 使用真实 COS 索引的副本、真实只读照片和临时文件夹来源，在 1280×900 记录切换前后位置及截图；构建版和安装版均执行。旧安装版作反例。
4. 版本 4.9.1，与 package-lock、CHANGELOG 同步。本机正常退出旧应用，保留一份 4.9.0 恢复副本后安装并启动。仅本地提交，不 push；主目录既有未提交文档不触碰，按原合并门禁不把代码并入脏的 main。

## 数据流与风险

App 的标签/页面记忆 → 共享滚动 hook → 网格/列表恢复；记忆中的已加载数量 → COS 两条分页链路 → 足够内容后恢复锚点。无后台隐藏页面及后台页面快捷键。

最脆弱前提是旧范围可一次读回：接口有 1000 张上限，已用继续补页覆盖此情况；数据变少时夹紧到有效滚动范围。恢复副本仅保留至用户确认 4.9.1 可用，回滚只替换 .app，不触碰用户数据。没有新增服务、凭据或用户配置。
