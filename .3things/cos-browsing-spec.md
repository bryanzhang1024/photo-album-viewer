# Photo Album Viewer · Mac 浏览体验需求草案

日期：2026-10-02。状态：讨论稿；已确认需求与暂定设计规则分开。仅记录规格，未授权实现、重写或数据迁移。

## 1. 要解决的问题

用户报告 Collection/300 整理后平铺了 9300 多个套图文件夹。按目录直接浏览难以选择，PictureView 连续换套体验吃力；现有 Cos 模式虽然能分类找套图，但左右换套、Esc 返回、列表位置恢复及原有功能衔接不完整。

产品目标：帮助用户找到、连续欣赏、收藏和筛选现有图片，并把喜欢的原图直接交给其他软件。

## 2. 给谁、在什么场景

- 用户本人，主要使用 Mac，浏览自己维护的原始文件目录。
- 有明确兴趣时按署名或角色找作品，没有明确目标时浏览全部作品或随机看套图。
- 浏览中删除不想保留的单张照片，或者将喜欢的照片拖到网页、聊天软件。
- Mac 先行是本轮建议范围；iPhone/iPad 暂缓，可由后续讨论调整。

## 3. 做到什么算成功

- 从某个分类结果进入套图后，可用左右键连续换套，无需每次返回手工点击。
- Esc 逐层返回，列表保留浏览上下文，不需要重新找刚才的位置。
- 原有随机、排序、收藏、缩略图大小及大图浏览能力得到完整继承。
- 不想保留的单张原图可移入废纸篓；喜欢的原图可从缩略图直接拖给支持文件接收的外部软件。
- 用户在文件管理器中添加或移除作品后，看图软件能够更新显示。

## 4. 本次要做（用户已确认）

1. 两种 Cos 进入路径：固定入口直达；沿文件夹打开登记为图库的 300 时自然进入分类浏览。
2. 分类方式：按署名（Coser 或组织）、按角色、全部作品。
3. 浏览层级：分类 → 套图列表 → 套内照片缩略图 → 单张大图。
4. 套内缩略图页面的左/右键换当前集合内的上一套/下一套；单张大图的左/右键换本套照片。
5. Esc 逐层返回；返回套图列表保留位置、排序、搜索及筛选条件。连续换套后，返回时定位最后看的套图。
6. 继承原软件浏览功能；对照原功能逐项核验，不能将本次改造缩减为两个快捷键修复。
7. 单张原图移入废纸篓。
8. 从照片缩略图拖出原始文件到外部软件。

## 5. 可验收要求

| 编号 | 行为与验收 |
| --- | --- |
| R1 | 从固定入口或登记过的 300 目录进入，均能得到同一图库的分类浏览能力。固定入口位置尚未定稿。 |
| R2 | 从半半子的套图列表按当前顺序进入其中一套，在缩略图页按右键进入该集合的下一套；不会跳到其他署名或整个磁盘目录的下一套。搜索、筛选和排序仍作用于整个集合。 |
| R3 | 打开单张大图时左右键仅翻照片；Esc 关闭大图回本套缩略图，再按 Esc 回套图列表。一个按键不能跨多层。 |
| R4 | 返回长列表时搜索、筛选与排序不重置；用户刚才看的套图出现在可见范围内，分页加载不能使位置恢复失效。 |
| R5 | 随机套图、排序、套图及照片收藏、缩略图大小与原有大图操作均有可用入口；功能清单以原软件为核对基线。具体分类排序字段尚待确定。 |
| R6 | 删除单张照片时真实原文件进入系统废纸篓，页面不继续显示该照片；失败时不误报成功，不主动永久删除。 |
| R7 | 从照片缩略图拖到支持文件拖入的网页或聊天软件，接收方拿到对应原文件，文件名、格式与内容保持一致；可用文件内容哈希核对。不是缩略图缓存、截图或内部 URL。源文件仍留在原位置。 |
| R8 | 在文件管理器中放入新套图或删除套图后，至少通过刷新可更新列表及有效计数；外部变更不导致误删除其他文件。 |
| R9 | 连续换套不每次重扫整个图库；长列表与缩略图加载不阻断键盘导航。具体性能门槛在实际图库环境中明确。 |

上述是未来实现的验收要求，不代表当前软件已经通过。

## 6. 本次明确不做

- 手机和平板访问、远程图库服务、跨设备同步、云端上传和离线图库管理，按当前 Mac 先行建议暂缓。
- 看图软件内下载套图、批量整理目录、整套删除、移动、改名、元数据编辑；这些由用户在文件管理器中操作。
- 为图库导入而强制复制全部原图到另一套管理库。
- 自动替用户在目标软件中点击发送或发布。
- 仅因讨论原生设计而直接重写 Swift/SwiftUI。

## 7. 暂定假设、风险与边界

- 建议按统一浏览器呈现普通目录和 Cos 图库；侧栏、顶部导航、标签及窗口结构待设计讨论。
- 建议随机套图作用于当前集合，同一套图/照片在不同分类入口共用收藏状态；尚未逐项确认这些细则。
- 删除后的计数、封面、收藏状态需要一致更新；最后一张图片删除后的空套图处理待定。
- 单张拖出是最低范围；多选拖出、大图拖出暂不作为已确认要求。
- 目标应用必须接受文件拖放；网页上传、聊天附件接收后的行为由目标应用决定。
- 外部变更的自动检测时机、断开硬盘处理、目录重命名后的收藏定位待定。
- 首尾套图边界是否循环、切换套图后的默认照片位置、普通目录与 Cos 的收藏兼容细节待定。
- 不把讨论中确认删除功能视为本轮真实删除文件的执行授权。

## 8. 现有项目约束

- 保持源文件目录由用户维护；原图拖出以现有原文件为来源，应用缓存仅服务显示。
- 当前是 Electron 项目；Apple 原生体验是设计探索，技术栈是否变化另行决策。
- 旧 .3things/spec.md 是历史 MVP 规格，不作为本轮不可变约束。
- 实现时必须遵循 AGENTS.md 的版本、测试、完整 .app 构建、本机安装和本地提交要求；当前仅文档讨论无需构建安装。

## 9. 最小版本与实现顺序（建议，未启动）

先完成主窗口及入口的设计审阅，再确定技术方案。首次交付应覆盖两种入口、当前集合连续换套、返回位置、原功能继承、单张丢废纸篓、原图拖出及外部变更刷新这一完整 Mac 使用流程；不把单个切片误称为全部需求完成。

## 10. 验证与撤回方式

- 使用测试图库验证删除、外部增删与收藏状态，不对真实图库做未经授权的破坏性测试。
- 用用户常用且接受文件拖放的网页和聊天软件验证原图接收；不为测试发送消息或公开上传。
- 长列表及换套在实际规模上进行只读性能验证。
- 文档与实现分别提交；源数据迁移不属于本轮范围。废纸篓中的图片保留系统可恢复路径。
- 当前只验证文档边界、需求归属与 Git 差异，未开展软件运行验收。
