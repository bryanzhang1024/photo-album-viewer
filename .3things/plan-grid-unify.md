状态：计划阶段产物，2026-10-26；晚间按用户四项拍板更新。**S1 已交付 4.4.2，S2+S3 已交付 4.5.0**（见第六节各片完成记录）。S4（收藏页卡片并入）按用户要求停下，未做。
取证：`.3things/acceptance/evidence/cos-vs-folder/`（4 张 1280×800 截图 + DOM 实测 `measurements.json` + 复现说明 `README.md`）。
方法：隔离 profile 启动 4.4.1 构建，两个入口指向同一份真实图库（300-Cos套图库，9,591 套），同窗口尺寸截图并测量。

> 现在还有一个问题，就是 COS 图库展示的东西和照片来源展示的有出入，网格界面长得不一样，有点割裂。这个问题首先可能要找出到底哪里不一样，然后再看怎么改。先做计划吧，先分析，先找原因之类的

## 一、结论（先看这一屏）

同一批 9,591 套图，两个入口是**两套并行实现**，不是"一个界面换数据源"：

- 文件夹侧用的是 4.0 新写的 `VirtualGrid + GridCard`（虚拟滚动、密度三档、排序、收藏、选中）；
- COS 侧沿用旧版 `.cos-grid + .cos-card`（CSS 自动分列、全量渲染 + 分页加载），`cos.css` 只是把 `folder.css` 的卡片文字规则抄了一遍。

所以差异分三层：**列数/卡宽不同（最直观）→ 卡片内容口径不同（名字、次行、封面、张数）→ 页头控件与可做的操作不同（排序、密度、收藏、面包屑、搜索位置）**。

另查到一条独立的代码缺陷，它放大了第一层差异：文件夹网格的默认缩略图密度算错了，没设置过密度的文件夹默认落在"紧凑"档（148px），而 COS 固定 168px。于是 1280 宽下文件夹 6 列、COS 5 列——这正是"网格长得不一样"最刺眼的一处。

## 三、卡片内容口径差异（同一套图，两处显示的东西不同）

| 字段 | COS 侧来源 | 文件夹侧来源 | 证据 |
|---|---|---|---|
| 名字 | `cosset.json` 的 `display_name`，并按丙方案去掉当前署名前缀与末尾作品括号 | 磁盘目录名原样 | `data/cos.js` `describeSet()` / `data/directory.js` `toFolderItems()` |
| 次行 | 作品或类型 + 张数（「原创写真 · 33 张」） | 张数 + 目录修改日期；容器目录则为子文件夹数 + 张数 | `CosSetListPage.jsx:61` / `GridCard.jsx:66-69` |
| 张数 | **递归整棵子树**（套内所有子目录的媒体） | **只算当前层直接图片** | `CosCatalogService.parseSetDirectory()` 的 `visit()` 递归 / `facts.directMediaCount` |
| 封面 | 索引时第一张媒体，单图 | 容器目录 2×2 拼贴（≥3 张样本），不足时向下找 1–2 层 | `GridCard.jsx:12-45` + `FolderCoverService` |
| 收藏 | 卡片上没有入口 | 封面右上角心形（悬停显示，收藏后常显） | `CosSetListPage.jsx` 无 heart / `base.css:631` |
| 排序 | 固定按名称，无控件 | 四字段 + 升降序 + 按文件夹记忆 | `FolderPage.jsx:488-515` |
| 新鲜度 | 索引快照，手动「刷新索引」才更新 | 每次进入实时读 + 监听当前目录（4.4.0） | `CosLibraryService` / `watchDirectory` |

覆盖范围另有一层：COS 只索引 `cos-library-roots-v1.json` 里的根（当前只有 300 一套），照片来源是 `library-sources-v3.json` 另一份注册表（Collection / 1TB-2 / 400 / 600 / Downloads 等）。两者本来就可能不同；本轮核对到 300 这一层数量一致（9,591），所以"有出入"的主体是**同一批图的展示方式**，不是少了一批图。

## 四、根因

1. **4.0 只重写了文件夹侧**。`src/ui/features/folder/` 是新组件，COS 页面从旧版搬了 DOM 和样式（`cos.css`），两套并存。
2. **卡片视觉规则有三份拷贝**：`folder.css`（GridCard）、`cos.css`（cos-card）、`favorites.css`（fav-card）。`tokens.css` 只统一了颜色/字号，没有统一"卡片由哪些元素、多宽、几行"。
3. **两套数据模型没有适配层**：目录快照（一层、直系）与 Cos 目录（一套、递归）直接喂给各自的页面，字段口径差异就漏到界面上。
4. **页头/工具栏按 `location.kind` 分支拼装**，没有"页面工具条契约"：搜索在文件夹页放工具栏、在 COS 页放页头；网格/列表切换和排序/密度只给文件夹页。
5. **默认密度缺陷放大列数差异**：`prefs.js:71-78` 里 `Number(localStorage.getItem(...))`，键不存在时 `Number(null) === 0`，被当成合法的"紧凑"档（148），默认本应是标准档（168）。于是没手动调过密度的文件夹是 6 列，COS 固定 168 是 5 列。
6. **验收口径只对设计稿，没有"两个入口并排"的一致性断言**。CSS 拷贝和字段差异因此一直没被发现。

---

## 五、统一方案

**选定：共用网格与卡片基元（B 方案）。** 把 `GridCard` 升为通用卡片、`VirtualGrid` 升为通用网格，COS 三页（全部作品/按角色/按署名、套图内照片）和文件夹页、收藏页都用同一份；差异只允许出现在"卡片文字内容"，不允许出现在尺寸、字号、间距、页头控件与操作上。

**2026-10-26 用户拍板：以照片来源为基准，COS 往照片来源靠。** 只有"套图卡下面显示的文字"保留 COS 图库规则：名字用清理后名字（去掉当前署名前缀、末尾作品括号），次行用「作品/题材 · 张数」。其余全部与照片来源一致——包括默认缩略图密度（按照片来源现状，紧凑 148，1280 下 6 列）、卡片结构、页头、搜索位置、排序/密度/收藏、右键/键盘/自动刷新。

**备选（不推荐）：只改 CSS（A 方案）。** 把 `cos.css` 的列宽/间距改成引用 `tokens.css`，一天内能让"看起来像"，但两套 DOM、两套交互、两套字段口径仍在，下一次改动继续发散；也解决不了"页头控件和操作不同"。

### 需要守住的一条数据事实

套图是叶子目录（没有子目录可拼），封面用单张；容器文件夹继续 2×2 拼贴。这不属于需要统一的"风格差异"，与照片来源进入 300 目录时看到的叶子卡片行为相同。如果以后要连套图卡也用拼贴，需要另行确认，不在本次范围。

## 六、分步计划（2026-10-26 拍板后修订）

每一步都能独立合并、独立看到效果；S1 做完两处网格就一致，S2 做完页头一致，S3 做完操作一致。

### S1 · 共用网格与卡片，COS 对齐照片来源（已交付 4.4.2 · 2026-10-26）

- 做什么：
  - `GridCard` 提到 `src/ui/components/`，入参改为卡片模型（名字、次行、封面节点、收藏、选中、角标），封面由调用方给（目录拼贴 / COS 单图）。
  - `VirtualGrid` 提到 `src/ui/components/`，加 `hasMore/onLoadMore`，COS 的 60/120 分页数据用它渲染。
  - COS 三个页面改用这两个组件；`cos.css` 里 `.cos-card/.cos-name/.cos-meta/.cos-cover` 与三套 `minmax` 列宽规则删除。
  - 默认缩略图密度明确为"紧凑"（148）：`getFolderDensity` 缺省值从"靠 `Number(null)=0` 意外落到紧凑"改成显式返回 0，照片来源观感保持不变；COS 跟随同一密度，1280 下同为 6 列。
  - 卡片文字按来源走两个模板：COS 用 `describeSet()`（清理名 + 作品·张数），文件夹用 `GridCard` 现有规则；版式、字号、行数一致。
- 用户看到：COS 网格从 5 列变 6 列、卡片变窄，和照片来源完全同宽同高；两处名字下面都是两行，只是文字内容按来源不同；COS 页也能调缩略图大小。照片来源外观不变。
- 验收：1280×800 截图 A/B、C/D 并排，列数、卡宽、封面高、圆角、名字/次行字号行高逐项一致（DOM 测量差值 ≤0.5px）；9,591 套仍能顺滑滚动、分页触发正常；`npm test`、`npm run build`、安装到 `/Applications` 后实机对比。
- 风险：COS 分页接虚拟滚动是主要技术点（`useCosPagedList` 60/页、套内 120/页）；接不上则退化为"虚拟网格 + 底部加载提示"，需在交付时说明。
- **完成记录（2026-10-26）**：共用组件落在 `src/ui/components/`（GridCard、VirtualGrid、card.css、cardModel），COS 四页与文件夹页已接入；默认密度改为显式紧凑 0；`cos.css` 重复规则与「继续滚动加载」已删除。全量测试 49 个套件 / 499 个用例通过，`npm run build` 通过，安装 4.4.2 到 `/Applications`，`npm run evidence:cos-grid` 对构建产物与安装版各跑一次，12/12 一致性断言通过。证据见 `acceptance/evidence/cos-vs-folder/`。

### S2 · 页头与搜索统一（已交付 4.5.0 · 2026-10-26）

- 做什么：
  - COS 页补面包屑（Cos 图库 › 按署名 › 半眸子）、排序（名称等字段 + 升降序）、缩略图密度、收藏入口。
  - 搜索统一进工具栏：COS 页头的搜索框删掉，⌘F 在两类页面都聚焦工具栏搜索；COS 页目前没有列表视图，工具栏的网格/列表切换对 COS 隐藏，搜索保留。
  - 状态栏提示按"本页真的能用的键"重新对齐（COS 页补上搜索/网格/列表/刷新等）。
- 用户看到：两个入口的页头控件位置、数量、图标一致；COS 页也能按名称/张数排序、调缩略图大小，⌘F 位置不再是两个地方。
- 验收：两入口页头控件清单一致（面包屑/排序/升降序/密度/收藏/设置）；⌘F 在两类页面聚焦同一位置；`npm test`、`npm run build`、安装 + 实机。
- 风险：COS 排序字段与数据层 `listSets` 的排序参数要对应（现只支持名称）；若要做"张数"排序需确认是否复用现有接口。
- **完成记录（2026-10-26）**：COS 列表/角色/照片页补可点面包屑、排序与升降序（套图列表：名称/图片/修改日期；照片页：名称/大小/修改日期）、缩略图密度、设置入口；搜索统一进工具栏，⌘F 在 Cos 页生效，页头搜索框删除；状态栏提示按可用键重写。

### S3 · 交互补齐（已交付 4.5.0 · 2026-10-26）

- 做什么：
  - COS 套图卡片补收藏心形（收藏身份落到现有按路径收藏模型）、选中态、右键菜单（打开/新标签/收藏/在 Finder 显示）。

## 八、本轮边界

- 不改需求、不改设计稿；以照片来源当前实现为基准（心形在封面右上角、悬停显示），不按旧设计稿调整位置。
- 不动主进程数据层（`CosCatalogService` / 目录契约 / 收藏格式），除非 S3 的收藏身份确认必须小改。
- 不做跨来源全库搜索、多选批量操作（backlog 已记事，不混进来），不改 COS 索引根目录的划分方式。
- 开工条件：用户明确说「批准 / 开始」后，从 S1 开始；每片完成并实机验证后再进下一片。
