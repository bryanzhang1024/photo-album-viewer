## 一、代码结构（4.1 首选，界面不动）

1. **拆分主进程 `main.js`**
   现状 1,376 行：窗口创建、IPC 注册、服务装配、启动流程、持久化路径混在一起。
   做：拆成 window / ipc / services 装配 / startup 四块，`main.js` 只留启动入口。
   验收：`main.js` 小于 200 行；现有测试全过；冷启动与窗口行为不变。
   触发：4.0 合并后，界面已稳定。
2. **持久化统一出口**
   现状 8 处直接拼 `userData` 路径、多个 JSON 文件各自读写。
   做：一个 storage 模块统一负责路径、schema 版本、读写与迁移。
   验收：所有 JSON 只经该模块；旧文件自动迁移且可回滚。
   触发：与第 1 条同批。
3. **整理 Cos 相关 IPC 通道**
   现状 18 个通道只服务 Cos，与目录通道并列，命名与边界不统一。
   做：按服务归并、统一命名；旧通道标 deprecated 保留一个版本。
   验收：通道数量下降，无调用方遗漏，新旧通道兼容。
   触发：第 1 条完成后。
4. **合并两套随机 / 相邻换套逻辑**
   现状文件夹模式与 Cos 模式各一套；4.0 新界面合并导航后应只剩渲染层一份，主进程侧若仍有重复则一并处理。
   验收：同一份逻辑覆盖两个入口，行为一致。
5. **测试体系重建**
   现状旧界面测试随 4.0 退役。
   做：新界面行为测试（打开方式、每文件夹记忆、完整显示、文件列表）+ 主进程契约测试 + 性能基线（9,591 套 Cos、3,055 张平铺）。
   验收：CI 可跑；性能基线有数字记录。
