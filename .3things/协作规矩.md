# 协作规矩（2026-10-25 用户批准）

本文件管阶段切换与批准流程。项目原有的分支、版本、构建、安装规则见仓库 `AGENTS.md`；两者不冲突时同时生效，冲突时以 `AGENTS.md` 的交付要求为准并由 Agent 说明。

## 一、三个阶段

### 准备（想清楚）

- 做什么：读代码与材料、只读核对、讨论、画样张、写清单与规格。
- 不做什么：不写产品代码、不构建、不安装。文档可以改、可以提交。
- 结束时用户手里有：文档、样张、清单、规格。
- 进入下一段：用户说「清楚了」。

### 计划（写清楚）

- 做什么：分步计划 —— 几步、每步做什么、做完用户能看到什么、怎么验收、哪一步需要用户拍板。
- 不做什么：不动代码；不在计划里留「到时候再说」。
- 结束时用户手里有：带验收点的计划。
- 进入下一段：用户说「批准」。

### 实施（做出来）

- 做什么：按片写代码、测试、构建、截图或安装给用户验。
- 不做什么：不改需求、不改设计、不自行找替代方案。
- 结束时用户手里有：能打开用的软件 + 验收记录。
- 进入下一片：本片验收通过。

## 二、一眼判断阶段

看这一步结束时用户手里多出来什么：文档或样张 = 准备；带步骤和验收点的计划 = 计划；能打开用的软件 = 实施。拿不准时按更早那段算。

## 三、越界即失败

- 准备阶段看到代码问题只记录，不动手。
- 实施阶段遇到样张或规格没覆盖的地方：停 → 回准备 → 补规格或样张 → 重新批准那一段 → 再继续。
- 实施阶段唯一可自行决定的是实现手段（例如用哪个 IPC 接口），前提是不改变外观与行为。

## 四、每轮开头格式

先写阶段标签，再写三句话：这一步回答什么问题、做成什么样算对、用户能看到什么。写不出就不开工。

例：`准备 · 正在核对样张覆盖`。

## 五、批准定义

用户说「批准 / 开始 / 可以」才算批准；Agent 自己说「继续做」不算。批准记录写进 `.3things/project.md`，记时间、阶段和批了什么。

## 六、用户的三个刹车

1. 「这是准备还是实施？」
2. 「这步做完我能看到什么？」
3. 「你是不是自己改了设计或需求？」

## 七、skill 分工

- 准备：`3things`（阶段与进度）、`solve-the-need`（需求说不清时）、`problem-framing`（把问题问深）、`grilling`（用提问压测方案）、`apple-design`（样张的材质、动效、排版规则）、`decision-ready-reporting`（汇报按「要你决定什么」组织）。
- 计划：`think`（主力，写清最脆弱的假设与回滚方式）、`lint-and-validate`（先定验收口径）。
- 实施：`test-driven-development`（先写失败测试）、`lint-and-validate`（每批验证）、`hunt`（先找根因）、`neat-freak`（收尾对齐文档）。
- 跨会话：`cross-agent-history`（之前聊到哪、做到哪）。

其余 skill 按需调用，不预载。

## 八、变更方式

修改本文件先向用户说明改哪条、为什么，得到确认后再写入；不在实施中顺手改规矩。
