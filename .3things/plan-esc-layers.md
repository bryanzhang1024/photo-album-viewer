## 二、现状统计结论

同一个 Esc 现在有 7 种结果：关菜单、关信息面板、关查看器、取消选中、清空搜索、退一层、没反应。

- Esc 分散在四处各自实现：`FolderPage.jsx`、`cos/useGridSelection.js`、`ImageViewer.jsx`、`Menu.jsx`；`App.jsx` 没有全局 Esc。
- 三份规格互相冲突：`design/shell-spec-final.md` 第 15 条（浮层→查看器→退一级）、10-25 快捷键收口的「Esc 取消选中」、搜索规格 S05「Esc 清空搜索」。三条都做了，先后顺序没有统一。
- Cos 三个列表页（按角色/按署名、全部作品、套图照片）只接了「清选中/清搜索」，**没有接「退一层」**，按到底无反应。
- 顶层页（照片来源、我的收藏、Cos 总览）与设置窗口完全没有 Esc。
- ⌘↑「上一级」也只在文件夹页实现，Cos 页按了无反应。

## 三、统一规则（实施后写入规格）

Esc 每次只退一层，按页面层级，顺序固定：

1. 菜单/浮层打开 → 只关浮层；
2. 查看器 open → 信息面板开着先关面板；全屏时先退全屏；否则关查看器；
3. 焦点在搜索框：有搜索词 → 清空并退出输入框（页面不动）；没有搜索词 → 继续第 4 步；
4. 有上一层 → 退到上一层；没有上一层 → 无动作。

补充约定：
- 选中态和页面上的搜索词不单独占一层（B 方案）：选中随换页消失；页面级搜索词随位置变化清空。
- `⌘↑` 与 Esc 退层走同一个目标（Cos 页也生效）。
- 按住 Esc 不连续退多层（忽略按键重复）；输入法组字中不拦截（`isComposing`）。
- 查看器内其它键不变（`⌫` 仍关闭、`Delete` 仍删）。

### 父级映射

| 当前位置 | Esc / ⌘↑ 去向 |
|---|---|
| 文件夹（非根） | 上一级目录（不带 siblings） |
| 文件夹（来源根） | 「照片来源」页 |
| Cos 套图照片页 | 对应套图列表（由打开时的入口与署名决定，见下） |
| Cos 套图列表（某角色/某署名） | 「按角色」/「按署名」入口页 |
| Cos 套图列表（全部作品） | Cos 总览 |
| Cos 按角色 / 按署名入口页 | Cos 总览 |
| Cos 总览、照片来源、我的收藏 | 无动作（顶层） |
| 设置窗口 | 无动作（独立窗口，关窗用 ⌘W） |

- 套图照片页的父级由 `origin` 决定：`viewKind` + `entityId/entityName` → `{ kind:'cos-sets', viewKind, entity }`。缺 `origin` 时按「全部作品」处理；`viewKind` 是 characters/cosers 但没有 `entityId` 时退回入口页，避免出现「全部作品」标题的错位页。
- 「按页面层级」而非浏览历史：从我的收藏点进文件夹再按 Esc，回该文件夹的上一层目录，不回收藏页；「回来路」留给 ⌘[。
- Esc 退层沿用 `navigate()`，与点面包屑一致（会写入标签历史）。

### 连带的面包屑修正

套图照片页面包屑现在只有「Cos 图库」一段（从全部作品进入时），既点不回全部作品列表，也和 Esc 的父级不一致。本次补一段：

- 全部作品进入：`Cos 图库 › 全部作品`；
- 按角色/按署名进入：`Cos 图库 › 按角色/按署名`（不变），有署名再加署名一段（不变）。

点各段分别回 Cos 总览 / 全部作品列表 / 入口页 / 署名套图列表。
