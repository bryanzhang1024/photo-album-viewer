# 产品三件事 · 当前有效规格

## 1. 要解决的问题

整理后的 Cos 收藏已经具备约 8,900 个稳定套图和结构化 `cosset.json`，但现有观看入口仍有断层：

- Finder/PictureView 看单套很舒服，却不能从角色或 Coser 聚合找套图。
- Immich 能从外网访问，但会把约 33 万张图片展开为资产瀑布流；其标签作用于图片，不是套图。
- 现有 Photo Album Viewer 已经能把文件夹当相簿，但只理解目录名和路径，不理解 `cosset.json` 中的角色、Coser、服装和作品。

本轮要把 Photo Album Viewer 变成套图级入口，让用户先找到“哪一套”，再进入套图看图片。

## 2. 给谁、在什么场景

- 目标用户：收藏的维护者本人。
- 本地场景：Mac 已挂载 1TB 与 CosPool 两块盘，希望按角色或 Coser 浏览，选中套图后在应用内或 PictureView 看原图。
- 后续远程场景：在笔记本或手机的局域网外访问同一套分类结构；该场景不进入本地 MVP，但本轮架构不得把它堵死。

## 3. 做到什么算成功

### 核心结果

- 用户无需记目录在哪块盘，能从“角色”或“Coser”进入，并在套图层级找到目标。
- 任一分类结果展示套图卡片，不在进入套图前展开单张图片。
- 源图库在索引、浏览、刷新、打开 PictureView 的全过程中没有新增、修改、移动或删除。

### 当前图库验收基线

- 总套图：8,891。
- 角色：1,287；Coser：587；服装/造型：4,766。
- 角色“初音未来”：110 套。
- “初音未来 → 兔子洞”：7 套。
- “初音未来 → 韶华”：4 套。
- Coser“星之迟迟”：340 套。
- 角色“普利瓦蒂”：1 套。

这些数字用于当前真实图库的烟雾验证，不写死为产品常量。

### 体验底线

- 有缓存时进入 Cos 图库后 3 秒内出现首屏套图卡片；分类切换应即时响应，不重新扫描全部原图。
- 首次建立索引时必须显示明确进度，界面不假死；完成后生成可删除、可重建的本地缓存。
- 8,900 级套图列表滚动时继续使用虚拟化，不一次挂载全部卡片 DOM。

## 4. 本次要做

### 4.1 Cos 图库入口

- 在应用主页增加“Cos 图库”入口，与现有普通目录浏览并存。
- 第一次进入时选择一个或多个 Cos 图片根；本机首批使用两个 300 根。
- 设置中能看到已配置根、可用状态、最近索引时间和“刷新索引”。

### 4.2 只读目录索引

- 发现每个套图目录中的 `cosset.json`，读取稳定 ID 和分类字段。
- 枚举该套图的直接图片，得到封面候选、图片数量和套图位置。
- 同一稳定 ID 出现在多个根时合并为一个逻辑套图，并保留多个只读位置。
- 索引缓存只写入 Electron `userData`，不写入媒体目录。
- 单个 JSON 损坏、目录暂时离线或图片为空时记录错误状态，不让整库失败。

### 4.3 展示逻辑

首页至少提供：

1. 按角色
2. 按 Coser
3. 全部套图

按角色：

```text
角色卡片 → 该角色的服装/造型卡片 → 套图卡片 → 套图图片
```

- 角色卡片显示名称、套图数和代表封面。
- 服装卡片只统计当前角色下的套图。
- 没有 `looks` 的套图进入“未细分”。
- 无法确定角色—服装对应关系的多角色/多服装套图进入“混合／未拆分”。

按 Coser：

```text
Coser 卡片 → ta 的全部套图
```

- Coser 页面显示套图卡片。
- 可用角色、作品、服装作为结果页筛选项，不再强制增加一层导航。
- 没有可靠 Coser 的套图可从“未知 Coser”进入，但不污染已知 Coser 统计。

全部套图：

- 支持按显示名、Coser、角色、服装、作品搜索。
- 搜索结果仍是一套一卡。

### 4.4 套图卡片与打开方式

- 套图卡片显示：封面、`display_name`、图片数、Coser、角色、服装、作品，以及源盘离线状态。
- 点击卡片进入现有相簿页，复用虚拟网格、缩略图缓存和内置 Image Viewer。
- 提供“在 Finder 中显示”。
- 提供“用 PictureView 打开”；默认以套图第一张图片启动 PictureView，使 PictureView 能继续浏览同目录图片。
- 未安装 PictureView 或调用失败时给出明确提示，并保留 Finder 入口。

### 4.5 为外网版保留的服务边界

本地 MVP 不启动 HTTP 服务，但索引与查询必须封装为独立、无界面的 `CosCatalogService`：

```text
CosCatalogService
├── buildIndex(roots)
├── listCharacters(query)
├── listLooks(characterId, query)
├── listCosers(query)
├── listSets(filters, page)
├── getSet(setId)
└── listSetMedia(setId, page)
```

- Electron 主进程通过 IPC 适配该服务。
- 渲染层只接收稳定的 `setId`、`mediaId` 和可显示字段，不接收可任意提交的绝对路径。
- 下一轮外网版通过只读 HTTP 适配器复用同一个服务，不再重新实现分类规则。

建议的逻辑记录：

```text
CosSetRecord
  id
  displayName
  locations[] { rootId, relativePath }
  cosers[]
  characters[]
  looks[]
  works[]
  themes[]
  type
  imageCount
  coverMediaId
  status
```

## 5. 可验收要求

- 当两个 300 图片根均在线并刷新索引时，用户可以看到 8,891 个逻辑套图；验证方法：界面统计与独立只读统计脚本一致。
- 当用户选择“按角色 → 初音未来”时，可以看到 110 套；验证方法：结果计数及套图 ID 集合与 `cosset.json` 基线一致。
- 当用户继续选择“兔子洞”时，可以看到 7 张套图卡片；选择“韶华”时看到 4 张。
- 当用户选择“按 Coser → 星之迟迟”时，可以看到 340 套，并能继续按角色或作品缩小结果。
- 当用户选择“普利瓦蒂”时，可以看到 1 套并打开原始套图。
- 当用户点击任一套图卡片时，应用复用现有相簿页显示该套图片，不复制图片。
- 当用户点击“用 PictureView 打开”时，PictureView 打开该套第一张图片并能继续浏览同目录；PictureView 不可用时应用显示可理解的失败提示。
- 当某个源盘离线时，其他在线根仍可浏览；离线套图显示“源盘不可用”，应用不把它们当成已删除。
- 当 `cosset.json` 损坏时，该套进入索引错误清单，其余套图正常可用。
- 当刷新、搜索、浏览和打开外部查看器完成后，媒体根的文件数量与 `cosset.json` 修改时间保持不变。
- 当用户退出 Cos 图库时，现有普通目录浏览、收藏、标签页、随机浏览和相簿查看行为保持不变。

## 6. 本次明确不做

- 不开放局域网或公网访问。
- 不接入 Immich API，不同步 Immich 标签或相册。
- 不给图片写 EXIF/IPTC，不生成 XMP sidecar。
- 不修改、移动、重命名或删除任何套图和原图。
- 不把 301 视频库纳入 MVP，不新增视频播放器。
- 不做 AI 图像识别、人脸识别或自动纠正标签。
- 不做标签编辑器、元数据批量修订或别名管理后台。
- 不在第一版自动合并 `Fate/Grand Order` 等文本别名；先按当前元数据精确值展示并记录数据质量问题。
- 不做手机端应用。

## 7. 暂定假设、风险与安全边界

- 风险：8,891 个 JSON 与 33 万图片的首次枚举可能较慢。处理：索引构建放在主界面渲染之外，显示进度，结果缓存；分类查询只读缓存。
- 风险：多角色、多服装数组没有配对关系。处理：不生成笛卡尔组合，进入“混合／未拆分”。当前约 14 套同时满足多角色和多服装，影响范围有限但必须正确处理。
- 风险：两块盘可能离线或卷名变化。处理：使用 `rootId + relativePath`，离线不删除索引；用户明确刷新后再更新可用状态。
- 风险：同一稳定 ID 可能跨根出现。处理：按 ID 合并逻辑记录，媒体位置去重；显示来源状态。
- 风险：真实套图包含私人收藏内容。处理：MVP 不联网、不上传、不记录图片内容；缓存只保存分类摘要与缩略图。
- 风险：为外网预留接口可能导致过度设计。处理：只建立可序列化的服务边界，不在本轮实现服务器、账号或网络协议。

## 8. 现有项目约束

- 继续使用现有 Electron、React、MUI、Sharp、虚拟列表和缩略图体系。
- 第一版不新增 npm 依赖；若实现时发现确需新依赖，必须先说明影响和撤回方法并获得确认。
- 不破坏普通目录浏览的数据契约；Cos 模式使用独立 IPC 通道和独立缓存命名空间。
- 功能实现必须在独立 `codex/<task-slug>` 分支完成。
- 用户可见功能交付时更新版本、`package-lock.json` 与 `CHANGELOG.md`；预计为向后兼容新功能，版本至少递增 minor。
- 每个纵切片运行针对性单测；最终至少运行 `npm test`、`npm run build` 与 `git diff --check`。
- 不 push、不发布、不部署，除非用户另行明确要求。

- 建立 `CosSetRecord`、解析器、查询接口和合成测试夹具。
- 用只读方式跑两个真实 300 根，验证 8,891/1,287/587/4,766 等基线。
- 产物可以由测试和命令调用，但还没有完整界面。

### 小片 1：第一条完整路径

- 打通“按角色 → 初音未来 → 兔子洞 → 7 套 → 打开套图”。
- 复用现有相簿页和缩略图服务。
- 这是本轮最关键的可演示切片；未通过前不铺其他分类页面。

### 小片 2：Coser 与全部套图

### 小片 3：本地使用闭环

- 增加多根配置、索引缓存/刷新、离线状态、损坏 JSON 错误清单。

- 完成性能与源目录只读验收。

### 本地真实使用验证

- 用户连续实际使用一段时间，确认角色优先和 Coser 优先两条路径都自然。
- 重点观察：是否总能在套图层级找到目标、服装层是否过细、是否需要作品作为第三个一级入口。
- 真实使用结论更新进度卡后，才开启外网版下一轮。

### 下一轮：外网 Web companion（不属于本次 MVP）

- 为 `CosCatalogService` 增加只读 HTTP 适配器。
- 服务只监听 `127.0.0.1`，所有媒体请求使用不透明 ID 并校验根目录边界。
- 提供响应式角色/Coser/套图页面，缩略图按需生成，原图与视频支持分页/Range。
- 通过 Cloudflare Tunnel + Access 暴露独立域名；部署前单独确认认证、域名、日志、缓存空间和撤回方式。
- 外网版验证通过后，再决定 Immich 是继续保留为辅助入口，还是只保留人脸/语义搜索用途。

## 10. 验证与撤回方式

### 自动验证

- 解析器：缺字段、空数组、非法 JSON、多位置同 ID、非 Cos 目录。
- 查询：角色 → 服装 → 套图、Coser → 套图、组合筛选、分页与自然排序。
- 安全：所有套图和媒体 ID 只能解析到已批准根内，拒绝 `..`、绝对路径注入和未登记根。
- 回归：普通目录浏览与现有相簿页测试继续通过。

### 真实图库验证

- 独立只读脚本生成一次当前基线，与应用索引结果比较套图 ID 集合和关键计数。
- 首次索引、缓存启动、源盘离线、损坏 JSON、PictureView 不可用分别走一遍。
- 操作前后比较媒体文件数、`cosset.json` 文件数和修改时间摘要，证明没有源目录写入。

### 撤回

- 功能代码独立分支；未合并前可直接停止使用该分支。
- Cos 索引与缩略图只在 `userData`，可从设置中清理并重建。
- 不做数据迁移、不改源图库，因此撤回不需要恢复媒体文件。
- 若合并后发现问题，从最新 `main` 新建修复分支；可临时隐藏 Cos 入口而不影响普通浏览。
