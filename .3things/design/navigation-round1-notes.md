# 第一轮 · 侧栏与入口

状态：等待用户选择。已确认“侧栏 + 网格”和沿现有 Electron 项目改造，这一轮不重开上述决定。

## 本轮只决定什么

侧栏应怎样组织文件夹浏览、Cos 图库、我的收藏、照片来源；署名、角色和全部作品应常驻侧栏还是位于主区顶部。

配色、图片卡片、缩略图大小、排序字段、大图查看器和文件操作不在本轮决策中；样张采用上轮相同内容和样式，避免把不同视觉风格混进导航比较。

## 三个候选

- 贴着做（浏览方式优先）：侧栏固定放“文件夹 / Cos 图库 / 我的收藏”，另列照片来源；三种分类在主区顶部。结构简洁，类别切换需要看主区。
- 取其神（分类入口常驻）：侧栏放普通浏览与收藏，Cos 图库组下直接列“按署名 / 按角色 / 全部作品”，另列照片来源。常用分类一眼可见，主区顶部只显示当前内容。Agent 推荐，用户尚未选择。
- 反着来（文件来源优先）：快捷入口保留 Cos 图库和收藏，下方保留“Collection → 300 / 400”的目录关系；分类在主区顶部。延续从目录找内容的习惯，目录层级较长时侧栏会变复杂。

三个方案都保留两条进入路径：固定 Cos 入口与已登记的 300 目录；两者进入同一个浏览框架，保留共同的标签、工具栏和后续看图操作。

“文件夹”只代表普通照片目录浏览，不提供下载整理或文件管理工具。

## 三屏与内容

每版含“从 300 进入”“按署名挑套图”“搜索无结果”。第一屏使用全部作品作为进入后的展示示例，不锁定默认分类或重启后的起始页面；实际默认是否恢复上次位置仍待决定。

图片、标题和照片数复用上一轮的六套半半子本机作品；120 为当时当前可访问根目录中的半半子目录数量。展示顺序仅用于对照，未运行正式图库排序。源图库不写入。

## 验证

- 静态模板检查通过，生成三版九屏自包含 HTML。
- 模板自带 headless 测量使用 --no-render 跳过；以平台提供的 Codex 应用内浏览器实际测量九屏边界，均无溢出。
- 36 个图片预览均加载成功，页面没有横向溢出。
- 窄面板中三版并排可见；1280 宽的桌面视口检查通过，临时视口覆盖随后复原。
- 三个“按署名挑套图”状态点击放大、截图与收起均成功。
- 页面可直接离线打开。仅静态设计对照，导航标签不操作实际图库；本轮不构建或安装应用。
