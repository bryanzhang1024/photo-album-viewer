# 收藏重连与 SourceRoot 迁移设计

## 背景

现有收藏以绝对路径保存。照片库从旧目录迁移到新的 Collection 目录后，路径失效，即使原相簿或照片仍然存在，收藏页也无法打开它们。

本次工作先对指定目录做一次性盘点，尽可能恢复已有收藏；同时让成功恢复和以后新增的收藏保存 SourceRoot 定位信息，避免 SourceRoot 根路径变化时再次逐条失效。

## 扫描范围与已知结果

只扫描以下目录：

- `/Volumes/Collection/300-Cosplayer`
- `/Volumes/1TB/Collection/400-Cos Album`
- `/Volumes/1TB/Collection/500-Cos专题`
- `/Volumes/1TB/Collection/600-Cos Weibo`
- `/Volumes/1TB/Collection/兴趣`

只读盘点共遍历 19,098 个目录和约 640,799 个文件，没有读取错误。

当前收藏中有 34 个失效相簿和 133 张失效照片。第二轮消歧后：

- 34 个相簿均可定位；
- 124 张照片可高置信度定位；
- 9 张照片暂不自动修复，其中 1 张有歧义，8 张在扫描范围内未找到。

报告中的数字以执行时重新读取的收藏快照为准。如果收藏版本或文件内容在预览与应用之间变化，应用操作必须拒绝执行并要求重新生成报告。

## 目标

1. 提供默认只读的一次性收藏重连工具。
2. 生成稳定、可审查的修复计划，不在扫描阶段写入收藏。
3. 只自动修复唯一且高置信度的匹配。
4. 最终写入前由用户明确确认。
5. 修复项和以后新增的收藏保存 `sourceId + relativePath`。
6. 收藏导航优先使用 SourceRoot 定位信息，保留旧绝对路径兼容。

## 非目标

- 不删除未匹配或有歧义的收藏。
- 不扫描用户未指定的其他目录。
- 不对全部媒体计算内容哈希。
- 不在应用后台持续自动搜索被移动的文件。
- 不自动改变 SourceRoot 注册表。
- 不承诺解决 SourceRoot 内部再次移动文件的问题；此情况可重新运行重连工具。

## 收藏数据模型

相簿、文件夹和照片收藏继续保留现有展示字段，并新增可选定位字段：

```js
{
  path: '/当前解析出的绝对路径',
  sourceId: 'src_...',
  relativePath: 'SourceRoot 内的可移植相对路径'
}
```

照片的 `relativePath` 指向照片文件本身；其现有 `albumPath` 继续保留用于展示和旧逻辑兼容。需要时可追加 `albumSourceId` 和 `albumRelativePath`，但仅在当前导航确实需要时引入，避免扩大数据模型。

读取规则：

1. 有合法 `sourceId + relativePath` 时，通过当前 SourceRoot 解析绝对路径。
2. SourceRoot 不存在时，项目状态为 `unresolvedSource`，不得猜测或删除。
3. 只有旧格式字段时继续使用 `path`，保证向后兼容。

写入规则：

1. 新增收藏时，只要当前页面具有 SourceRoot 边界，就同时保存定位字段。
2. 重连成功时更新 `path`，并写入目标所属 SourceRoot 的定位字段。
3. 保留收藏的 `id`、`addedAt`、名称、收藏集引用及其他展示元数据。

## 匹配策略

### 相簿

按以下顺序匹配：

1. 当前绝对路径存在：不处理。
2. 在扫描范围内按完整目录名寻找候选。
3. 唯一候选直接进入高置信度计划。
4. 多候选时利用已解析父相簿和相对路径消歧。
5. 仍有多个候选则保留原收藏并报告，不自动修复。

`02_Foot` 的两个同名候选可通过父相簿确定为 `500-Cos专题/樱岛麻衣` 下的目录。

### 照片

按以下顺序匹配：

1. 当前绝对路径存在：不处理。
2. 若原所属相簿已重连，优先检查新相簿中的原相对路径。
3. 再检查新相簿中的同名文件。
4. 必要时搜索扫描范围内的同名文件。
5. 收藏记录包含有效文件大小时，用大小过滤同名候选。
6. 父目录日期仅格式变化时，可用规范化日期消歧，例如 `weibo@2025-04-27` 对应 `weibo@20250427`。
7. 缺少足够证据或仍有多个候选时，不自动修复。

普通文件名（例如 `3.jpg`）且没有原文件大小时，禁止仅按名称自动匹配。`焖焖碳/015 - 可畏礼服/3.jpg` 不进入自动修复计划，因为新目录中的文件名已经变化且无法证明内容一致。

## 重连工具与数据流

工具分为两个明确阶段：

### 预览阶段

1. 读取 `favorites.json`、SourceRoot 注册表和指定扫描根。
2. 记录收藏文件版本及内容摘要。
3. 建立目录名、文件名及文件大小索引。
4. 生成修复计划，包含旧路径、新路径、匹配依据、置信级别和 SourceRoot 定位。
5. 输出汇总及可审查的明细报告。
6. 不修改收藏文件。

### 应用阶段

1. 必须显式指定已生成的修复计划。
2. 再次校验收藏版本、内容摘要、目标存在性和 SourceRoot 归属。
3. 任一前置条件变化则整体拒绝写入，不做部分更新。
4. 在写入前按全局备份规范创建 `.codex/backups/<timestamp>-reconcile-favorites/`，保存原文件与 `manifest.json`。
5. 以临时文件加原子替换方式写入新收藏数据。
6. 写入后重新读取并验证 JSON、收藏数量、保留项和所有计划项。

应用真实收藏数据属于高风险操作。即使用户已批准实现，最终应用阶段仍必须展示修复汇总并再次取得明确确认。

## 应用集成

收藏上下文在添加收藏时接收当前 SourceRoot 定位信息。收藏页面向浏览器导航层传递规范化目标；新格式项目直接使用 `sourceId + relativePath`，旧格式项目继续走现有绝对路径兼容分支。

应用不得在正常启动时自动运行重连扫描，也不得因 SourceRoot 暂时离线删除收藏。

## 错误处理

- 扫描根不存在或不可读：报告根级错误，不生成可应用计划。
- 收藏或 SourceRoot 数据格式错误：终止并报告，不写入。
- 目标在预览后消失：应用阶段整体失败。
- 收藏在预览后变化：应用阶段整体失败。
- 候选有歧义：保留原项目并写入报告。
- SourceRoot 无法唯一归属：保留原项目并写入报告。
- 备份或原子写入失败：保留原收藏文件并报告错误。

## 验证

自动化测试至少覆盖：

- 唯一相簿匹配；
- 父相簿消歧；
- 相簿映射后的照片定位；
- 文件大小消歧；
- 日期目录格式消歧；
- 普通文件名多候选拒绝自动匹配；
- 未匹配项目保持不变；
- SourceRoot 定位生成与解析；
- 预览后收藏变化时拒绝应用；
- 写入保留收藏 ID、时间和收藏集引用；
- 旧格式收藏仍可加载和导航；
- 新收藏写入 SourceRoot 字段。

实现完成后运行相关单元测试、`git diff --check` 和 `npm run build`。版本号按向后兼容的新功能提升 minor，并同步 `package-lock.json` 与 `CHANGELOG.md`。

## 最终验收

在不修改真实收藏的前提下生成最终预览。预览应明确展示：

- 自动修复相簿数量；
- 自动修复照片数量；
- 未修复及歧义项目；
- 每项旧路径和新路径；
- 匹配依据；
- 写入后使用的 SourceRoot 定位。

只有用户审查预览并明确确认后，才能执行真实收藏文件的备份和写入。
