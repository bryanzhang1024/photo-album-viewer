# 收藏相簿预览图恢复设计

## 背景

收藏重连已经把 39 个相簿的顶层 `path` 恢复到当前媒体目录，但相簿内部保存的封面字段仍可能指向旧绝对路径。收藏图片能够显示，是因为图片收藏的顶层 `images[].path` 已参与重连；相簿卡片则继续读取未参与重连的 `previewImagePath`、`previewImages[].path`、`previewSamples` 或 `samples`。

当前真实数据中：

- 39 个相簿目录均存在；
- 36 个相簿带封面元数据，其中 32 个首张封面路径失效；
- 32 个失效封面中，31 个可在当前相簿内按文件名唯一恢复；
- 1 个相簿的旧封面文件已不存在，需要重新选择当前相簿内的图片；
- 3 个相簿没有封面元数据，需要从当前相簿选择图片。

## 目标

1. 一次性恢复当前收藏相簿的预览图，保留相簿 ID、收藏时间及其他元数据。
2. 封面定位不再依赖不可迁移的旧绝对路径。
3. SourceRoot 根目录变化时，相簿路径和封面路径能够一起重新解析。
4. 封面元数据缺失或源文件消失时，收藏页仍能从当前相簿选择可用封面。
5. 所有真实数据写入前创建受控备份并验证目标文件。

## 方案比较

### 方案 A：只做一次性 JSON 替换

将当前失效封面路径改为现有文件路径。改动最小，但以后 SourceRoot 再次移动时仍会失效，属于治标方案。

### 方案 B：只在界面加载时动态扫描

忽略保存的封面路径，每次缺失时请求相簿图片。能够自愈，但增加运行时 IPC 和目录读取，已有可用封面定位信息也无法复用。

### 方案 C：封面相对定位 + 缺失回退（采用）

保存封面相对于相簿的路径；加载收藏时以已经物化的相簿路径重新组成封面绝对路径。旧数据没有合法封面时，从当前相簿选择第一张受支持图片作为回退，并将一次性恢复结果持久化。

该方案保持现有快速封面加载路径，同时解决再次移动和历史缺失两类问题。

## 数据模型

相簿收藏新增可选字段：

```js
{
  path: '/Volumes/1TB/Collection/album',
  sourceId: 'src_...',
  relativePath: 'album',
  previewRelativePaths: ['cover.jpg']
}
```

规则：

- `previewRelativePaths` 只能包含相对于相簿目录的可移植路径，禁止绝对路径和 `..` 越界路径。
- 保留 `previewImages`、`previewImagePath`、`previewSamples` 和 `samples` 作为旧格式兼容字段。
- 对新格式相簿，读取时优先由 `album.path + previewRelativePaths` 生成当前绝对封面路径。
- 保存时从现有封面绝对路径提取相对于相簿的路径，并写入 `previewRelativePaths`。
- 不为封面单独复制相簿已有的 `sourceId`；封面定位依附于相簿，避免重复状态漂移。

## 运行时数据流

### 收藏加载

1. 先通过 `sourceId + relativePath` 物化相簿当前 `path`。
2. 校验 `previewRelativePaths`，在当前相簿路径下生成封面绝对路径。
3. 将生成结果规范化为相簿卡片已经支持的 `previewSamples`。
4. 没有新格式字段的旧收藏继续使用现有封面字段。

### 收藏保存

1. 继续为相簿顶层路径附加 SourceRoot 定位。
2. 从 `previewSamples`、`samples`、`previewImages` 或 `previewImagePath` 收集封面路径。
3. 只保留位于相簿目录内的封面，写入 `previewRelativePaths`。
4. 不接受相簿目录外或无法规范化的路径。

### 收藏页回退

当相簿没有可用封面元数据时，渲染层请求当前相簿的图片列表并选择第一张受支持图片。回退仅用于显示；一次性盘点会把可恢复封面持久化，正常启动不执行全库扫描。

## 一次性恢复

扩展现有收藏重连引擎，为相簿封面生成独立变更：

1. 若旧封面在新相簿内按原相对路径存在，直接采用。
2. 否则在新相簿内按文件名匹配；唯一匹配时采用。
3. 若旧封面不存在、文件名也无法匹配，或相簿没有封面元数据，则按项目当前支持的媒体扩展名和稳定名称排序选择第一张图片。
4. 目标必须位于修复后的相簿目录内并真实存在。
5. 写入 `previewRelativePaths`，并同步旧兼容字段，使当前版本立即能够显示。
6. 不修改相簿数量、ID、名称、收藏时间或收藏集引用。

真实数据更新沿用现有 `.codex/backups/<timestamp>-.../` 备份、manifest、摘要校验和临时文件原子替换。用户在本任务中回复“执行”，已授权应用经测试验证的封面恢复计划。

## 错误处理

- 相簿目录不存在：不修改该相簿并报告。
- 相簿内没有受支持图片：不伪造封面，保留空状态并报告。
- `previewRelativePaths` 非法或越界：忽略该字段并回退旧格式/动态加载。
- 计划生成后收藏内容变化：拒绝应用，避免覆盖并发修改。
- 备份、目标验证或原子写入失败：终止应用并保留原数据。

## 测试与验证

自动化测试至少覆盖：

- 相簿物化时封面相对路径随相簿根目录变化；
- 保存相簿收藏时生成 `previewRelativePaths`；
- 拒绝相簿目录外和 `..` 越界封面；
- 一次性恢复原相对路径、唯一文件名和首张媒体回退；
- 没有可用媒体时保持未解决；
- 应用恢复计划保留所有非封面元数据；
- 收藏卡片封面缺失时通过当前相簿路径回退；
- 旧格式收藏继续正常加载。
